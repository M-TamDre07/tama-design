# Audit Website Tama Andrea Studio
**Tanggal audit:** 14 Oktober 2026  
**Repositori:** `M-TamDre07/tama-design`  
**Status:** Tahap audit dan pemeliharaan sumber selesai untuk cakupan di bawah. Migrasi database belum dimulai.

## Ringkasan eksekutif

Website adalah situs statis HTML/CSS/JavaScript yang di-deploy melalui Vercel, dengan API Google Apps Script dan Google Sheets sebagai sistem operasional saat ini. Formulir pesanan, pelacakan order, panel admin, notifikasi Telegram, data pelanggan, catatan kunjungan, transaksi, dan nota bergantung pada backend tersebut. Karena pilihan database baru belum diputuskan, integrasi lama sengaja tidak dihapus.

Selama periode pemeliharaan, halaman publik diarahkan ke `/maintenance.html`. Beranda lama dipertahankan sebagai `index-live.html` agar tidak hilang dan dapat ditinjau ketika situs akan dibuka kembali. Rute `/admin` tidak dimasukkan ke daftar pengalihan publik, sehingga jalur administrasi tetap terpisah dari tampilan pelanggan.

## Perubahan yang sudah masuk ke GitHub

### 1. Pemeliharaan dan pemulihan

- Membuat `maintenance.html` sebagai halaman mandiri yang tidak bergantung pada database untuk dirender.
- Mengarahkan beranda dan rute halaman publik utama ke pemberitahuan pemeliharaan melalui `vercel.json`.
- Menyimpan salinan beranda lama di `index-live.html`.
- Mengubah `sw.js` ke cache bernama baru agar aplikasi PWA tidak mempertahankan shell situs lama; halaman pemeliharaan menjadi fallback saat offline.
- Memperbarui metadata aplikasi dan menghentikan halaman divisi digital lama agar tidak lagi menjadi tujuan navigasi.
- Menyetel `robots.txt` agar crawler dapat membaca halaman yang menyatakan `noindex`. Saat pemeliharaan, memblokir semua crawler justru bisa mencegah mereka membaca instruksi `noindex`.

### 2. Identitas dan alur pelanggan

- Mengganti nama divisi desain grafis dari **TA Visual** menjadi **TA Studio** pada halaman publik dan kontrol navigasi.
- Menghapus divisi **TA Digital Works / Coming Soon** dari navigasi, kartu divisi, deskripsi SEO, sitemap dan sumber halaman publik.
- Mempertahankan keterangan *Coming Soon* yang ada pada layanan berbeda, yaitu fitur “Retain User’s Data iPhone”, karena itu bukan divisi TA Digital Works.
- Mengurangi informasi yang ditampilkan pada pelacakan order sebelum nama dan email diverifikasi.
- Mengubah bahasa jadwal servis agar tidak membeberkan pola waktu pribadi. Alamat/titik pertemuan diarahkan untuk dikonfirmasi secara pribadi.

### 3. Privasi lokasi

- Menghapus pin studio spesifik dari sumber publik terkini dan menggantinya dengan area umum Kalianda/Lampung Selatan.
- Menghapus peta satelit yang sebelumnya mencoba menampilkan lokasi studio dari beranda.
- Membuat tampilan area layanan yang tidak menampilkan alamat tempat tinggal.
- Memperbaiki formulir layanan kunjungan supaya nilai bawaan “lokasi studio” tidak terbawa saat pelanggan memilih teknisi datang ke lokasi.
- Memvalidasi tautan Google Maps pada backend dan sebelum tautan ditampilkan pada halaman pelacakan yang sudah diverifikasi.

**Catatan riwayat Git:** pin lama bisa saja masih ada pada commit historis karena Git mempertahankan histori. Perubahan sumber saat ini tidak otomatis menghapus data dari histori lama. Jika pin tersebut mengarah ke rumah atau lokasi privat, pertimbangkan penanganan histori yang terencana dan perubahan titik pada sumber peta aslinya sebelum situs dibuka kembali.

### 4. Transparansi data

- Menambahkan `privasi.html` dan tautan kebijakan privasi pada halaman publik. Dokumen menjelaskan data yang dapat diterima, tujuan penggunaan, penyimpanan, layanan pihak ketiga, permintaan koreksi/penghapusan dan kontak.
- Menjelaskan bahwa sistem saat ini menggunakan Google Apps Script/Google Sheets dan pemberitahuan operasional tertentu dapat diteruskan ke Telegram admin.
- Tidak menambahkan alamat Telegram atau email bisnis yang belum bisa diverifikasi. Kontak yang ditemukan di konfigurasi frontend adalah WhatsApp bisnis yang sudah dipakai situs.

### 5. Pemeriksaan dan hardening sumber backend

Perubahan berikut sudah tercatat pada file sumber `backend/google-apps-script/code.gs` di GitHub:

- Memperbaiki pembentuk respons JSON yang sebelumnya mencoba memanggil `TextOutput.setResponseCode()`, padahal metode itu tidak tersedia pada objek tersebut.
- Memindahkan pemeriksaan wajib, format email/nomor, kategori/metode layanan, batas panjang, batas lima software dasar, dan format request ID ke validasi server yang benar.
- Menambahkan pembatasan dasar percobaan order dan verifikasi pada server.
- Membuat endpoint pelacakan order publik tidak mengungkap keberadaan order, nama, layanan, atau status sebelum verifikasi.
- Menambahkan perlindungan terhadap formula injection pada penulisan data teks ke Google Sheets.
- Melakukan escaping terhadap nama layanan yang dikirim ke notifikasi Telegram.
- Mempertahankan field yang tidak dikirim ketika update order/customer parsial, sehingga update tidak mengosongkan field yang tidak sedang diedit.
- Mencegah penghitung order pelanggan bertambah hanya karena order lama diedit.
- Menghapus identitas admin dan password bootstrap tertanam dari versi sumber terkini; menambahkan mekanisme konfigurasi satu kali dan helper rotasi password untuk pelaksanaan manual dari editor Apps Script.

**Penting:** file Google Apps Script yang ada di GitHub adalah salinan sumber, bukan deployment runtime. Perubahan tersebut **belum live** sampai disalin ke proyek Google Apps Script yang dipakai situs, diuji, lalu diterbitkan sebagai deployment baru. Jangan membuka pemesanan hanya karena commit GitHub berhasil.

## Prosedur sebelum membuka situs lagi

1. Pastikan credential admin produksi sudah diganti dan sesi lama dicabut.
2. Sinkronkan `backend/google-apps-script/code.gs` yang ditinjau ke proyek Apps Script produksi; sesuaikan Script Properties yang diperlukan; deploy sebagai versi baru.
3. Uji health/status backend, ketersediaan layanan, penciptaan order uji, anti-duplikasi, tracking dengan kode acak, verifikasi nama+email, notifikasi Telegram dan panel admin.
4. Uji semua halaman utama dari HP dan komputer: beranda, TA Studio, TA TechCare, karya, tentang, bantuan, keluhan, privasi dan form order.
5. Jika hasil tes lulus, hapus pengalihan pemeliharaan yang ditambahkan di `vercel.json`; pulihkan `index.html` dari arsip yang ditinjau; hapus `noindex` khusus arsip dari beranda aktif; pulihkan shell cache PWA normal dengan nama versi baru; dan perbarui sitemap/robots.
6. Baru setelah sistem normal stabil, pilih database pengganti, susun pemetaan skema, rencana migrasi, pengujian rekonsiliasi data, prosedur rollback dan cutover. **Jangan menghapus Google Sheets atau Apps Script sebelum pengganti lolos pengujian.**

## Cakupan yang sengaja belum dilakukan

- Tidak ada pemindahan database; pilihan layanan database baru belum ditentukan.
- Tidak ada penghapusan spreadsheet, sheet, deployment Apps Script, bot Telegram, atau data pelanggan.
- Tidak ada penghapusan folder/asset CSS/JS lama hanya berdasarkan dugaan bahwa file itu tidak digunakan.
- Tidak mengklaim flow order/admin berhasil secara end-to-end, karena itu membutuhkan deployment Apps Script aktif dan uji runtime yang aman.
- Tidak menganggap situs telah siap dibuka kembali; status pemeliharaan tetap disengaja hingga pemeriksaan deployment dan backend selesai.
